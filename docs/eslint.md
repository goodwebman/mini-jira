# Как устроен ESLint

Проверки SonarJS, Unicorn, React, effects, Tailwind 4, browser compat, unused imports, комментариев и Perfectionist. Точный список, области действия и отличия от mobile: [eslint-mobile.md](eslint-mobile.md).

## Что добавлено

Основная конфигурация — [`eslint.config.js`](../eslint.config.js) в корне монорепозитория. Все workspaces используют её; отдельных конфигов с ослабленными правилами нет.

| Зависимость                         | Назначение                                                                                    | Статус                                  |
| ----------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------- |
| `eslint-plugin-boundaries`          | Проверяет направление зависимостей FSD, изоляцию слайсов, публичные входы и неизвестные файлы | Добавлена                               |
| `eslint-plugin-import-x`            | Находит неразрешённые импорты и циклы                                                         | Добавлена                               |
| `eslint-import-resolver-typescript` | Разрешает `@/*`, расширения TS/TSX и пути из настоящего tsconfig                              | Добавлена                               |
| `@eslint/js`                        | Базовый recommended-пресет JavaScript                                                         | Уже была                                |
| `typescript-eslint`                 | TS recommended-пресет, парсер и правила с информацией о типах                                 | Уже была; добавлены type-aware проверки |
| `eslint-plugin-react-hooks`         | Правила Hooks, зависимостей эффектов и проверки React compiler из recommended-пресета         | Уже была                                |
| `eslint-plugin-react-refresh`       | Совместимость экспортов компонентов с Fast Refresh                                            | Уже была                                |
| `eslint-config-prettier`            | Отключает конфликтующие с Prettier стилистические правила ESLint                              | Уже была; остаётся последним блоком     |

Версии зафиксированы в `package-lock.json`; новые пакеты — devDependencies корневого `package.json`. Новых зависимостей для тестов не требуется: используются `node:test`, `node:assert` и установленный ESLint.

## Порядок применения конфигурации

Flat config применяется последовательно, поэтому поздний блок может переопределить ранний:

1. **Игнорируемые каталоги.** `dist`, `dist-ssr`, `coverage`, `.vitest`, `.vercel`, `node_modules` на любой глубине не линтятся. Исходники и конфиги остаются под проверкой.
2. **Комментарии отключения.** Неиспользуемый `eslint-disable` — ошибка. Нужное отключение работает; устаревшее нужно удалить.
3. **Базовый JS.** Recommended-пресет действует на JS/JSX/MJS/CJS/TS/TSX.
4. **Node-окружение.** Скрипты, API и конфиги получают `process`, `Buffer` и другие Node globals. Этот блок исключает `apps/web/src`, чтобы Node API случайно не считались браузерными.
5. **Базовый TS.** TS/TSX получают TS recommended-пресет. Проверка неиспользуемых импортов и переменных передана `unused-imports`, базовые JS/TS `no-unused-vars` отключены во избежание дублей.
6. **Проверки с типами.** Исходники и тесты web/API/contracts подключаются к своим TS-проектам через `parserOptions.project`; `tsconfigRootDir` вычисляется относительно файла конфига, а не текущей папки терминала.
7. **Браузерный React и FSD.** Только `apps/web/src`: browser globals, React Hooks, Fast Refresh, TypeScript resolver, проверки импортов и архитектуры.
8. **Изоляция auth.** В `entities/auth/lib` запрещены зависимости от React, Axios, TanStack, Redux, contracts, alias приложения и его `model`/`api`; прямые browser globals заменяются внедряемым `AuthPlatform`.
9. **Prettier.** Последним отключает конфликтующие правила форматирования. Форматирование проверяет отдельная команда Prettier.

Для TypeScript правило `no-undef` отключается TS-пресетом: неизвестные имена проверяет TypeScript через `npm run typecheck`. Для JavaScript это остаётся задачей ESLint. Поэтому один `lint` не заменяет проверку типов.

## Новые правила с типами

| Правило                                   | Запрещено                                                      | Допустимо                                                              |
| ----------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `@typescript-eslint/no-floating-promises` | Оставить Promise без обработки: `save()`                       | `await save()`, обработка через `.catch(...)` или явное `void save()`  |
| `@typescript-eslint/await-thenable`       | `await 123`                                                    | `await save()` для функции, возвращающей Promise                       |
| `@typescript-eslint/no-misused-promises`  | Передать async-функцию туда, где ожидается синхронный callback | Синхронный callback, который явно обрабатывает или отбрасывает Promise |

Все три правила имеют severity `error` и действуют в исходниках **и тестах** трёх workspaces. Инфраструктурные конфиги, не входящие в эти TS-проекты, проверяются без этих трёх правил.

`void` явно отмечает запуск без ожидания, но само по себе не перехватывает rejection. Обработка ошибок должна быть внутри операции или в `.catch(...)`. В форме login существующая `submit` уже обрабатывает ошибку авторизации; обработчик изменён на `(event) => void submit(event)`.

## FSD и импорты

Слои: `app → pages → widgets → features → entities → shared`. Импортировать можно нижние слои. Соседние слайсы изолированы, а вход снаружи слайса разрешён через его публичный `index.ts`. Алиасы и относительные пути проверяются после разрешения до файла. Обычные импорты, реэкспорты, type imports и динамические импорты с литеральным путём проверяются.

Подробности и примеры — в [`fsd.md`](fsd.md). Особенности настройки:

- `app` и `shared` рассматриваются как слои без слайсов: прямые внутренние импорты разрешены.
- `main.tsx` может подключать `app` и корневой `index.css`.
- `.d.ts` классифицируются отдельно и не считаются неизвестной папкой.
- `entities/auth/testing.ts` разрешён только из тестов слоя app; это не общее исключение для любых тестов.
- Для Vite-импортов с `?raw` проверка `import-x/no-unresolved` отключена. Это исключение не подтверждает существование такого ресурса; его также проверяет сборка.
- Содержимое CSS `@import`, вычисляемые пути runtime и смысл кода без импортов не анализируются этими правилами.

Для прохождения строгих границ `App` перенесён в `app`, галерея — в `pages/kit-gallery`, добавлены публичные входы страниц и исправлены обращения к внутренним файлам auth.

## Как запускается и что блокирует

| Точка запуска       | Что выполняется                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run lint`      | ESLint всего репозитория; `--max-warnings 0` делает предупреждения причиной отказа                                                   |
| `npm run lint:fix`  | То же с автоматическими исправлениями; архитектурные зависимости автоматически не перестраивает                                      |
| `npm run test:lint` | Тесты реального поведения ESLint и подключения конфигурации                                                                          |
| `npm test`          | Сначала `test:lint`, затем сборка contracts и тесты contracts/API/web                                                                |
| `npm run validate`  | ESLint → Prettier → TypeScript → `npm test` → production build; ошибка останавливает цепочку                                         |
| lint-staged         | Для подготовленных JS/TS запускает ESLint через Node с `--fix --max-warnings 0`, затем Prettier; для TS также typecheck              |
| Husky `commit-msg`  | Проверяет сообщение, запускает lint-staged, затем ESLint всего рабочего дерева и typecheck; ошибки завершают hook ненулевым статусом |

lint-staged и `commit-msg` уже существовали. Для новой конфигурации отдельное подключение в hook не нужно: они вызывают корневой ESLint. `npm install` подключает Husky через существующий `prepare`. Тесты ESLint-конфига запускаются через `test:lint`/`test`/`validate`; **сам Git-hook их не запускает**.

Это локальные команды и Git-проверки. Обязательный запуск в удалённом CI и защита merge должны настраиваться отдельно; сам по себе Husky их не обеспечивает.

## Как устроены тесты

Все тесты находятся в [`scripts/eslint-config.test.mjs`](../scripts/eslint-config.test.mjs). Используются три способа проверки:

1. **Изолированная файловая структура.** Во временной папке создаются настоящие слои, слайсы и цели импортов. Загружается рабочий flat config; меняются только пути к fixture и отключаются три type-aware правила, поскольку файлы fixture не входят в настоящие TS-проекты. Временная папка удаляется после тестов.
2. **Настоящие TS-проекты.** `ESLint.lintText` проверяет короткие примеры по существующим путям исходников и тестов web/API/contracts. Конфиг и типы здесь не подменяются, исходные файлы на диске не меняются.
3. **Настоящий CLI.** ESLint запускается отдельным Node-процессом через stdin. Пример с одним предупреждением и без ошибок отклоняется при `--max-warnings 0` и проходит при лимите 1.

| Область         | Что проверяется                                                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Матрица FSD     | Все направления между шестью слоями через alias и относительные пути; разрешённые зависимости действительно проходят без диагностик |
| Слайсы          | Соседние слайсы, запрет deep imports, разрешённые внутренние пути и публичные динамические импорты                                  |
| Обходы          | Реэкспорт, `export *`, type import, динамический import, CSS-импорт, неизвестная папка и разрешённая цель вне известных FSD-папок   |
| Исключения      | Bootstrap, `.d.ts`, вход auth/testing, внутренние импорты app/shared, `?raw`                                                        |
| Импорты         | Неразрешённый путь, TS alias, цикл через реэкспорты, запуск из папки web                                                            |
| Type-aware TS   | Каждый из трёх Promise-правил: запрещённый и разрешённый пример в исходнике и тесте каждого workspace; отдельно async JSX-handler   |
| Базовые правила | Неизвестное имя JS, `any`, неиспользуемый TS-import и разрешённые аналоги                                                           |
| React           | Условный Hook, отсутствующая зависимость эффекта, смешанные экспорты Fast Refresh и разрешённые аналоги                             |
| Auth            | Каждая группа запрещённых импортов, каждый запрещённый browser global, разрешённая внутренняя зависимость и внедряемая платформа    |
| Окружения       | Browser/Node globals, отсутствие React/FSD-правил в Node-конфигах, сохранение проверки исходников                                   |
| Игноры          | Каждый исключённый каталог на корневом и вложенном уровне                                                                           |
| Отключения      | Неиспользуемый eslint-disable ошибочен, необходимый разрешён                                                                        |
| Пресеты         | Итоговая severity всех правил подключённых JS/TS/React-пресетов с учётом последнего Prettier-блока                                  |
| Подключение     | Команды package.json, параметры lint-staged, наличие staged/full-tree ESLint-проверок и возврата статуса в commit-msg               |

Для готовых сторонних пресетов проверяется подключение всех правил и поведение ключевых правил на примерах; полные внутренние тесты самих ESLint-плагинов здесь не дублируются. Проверка hook читает его подключение, реальный commit не создаёт и индекс Git не меняет.

Запуск:

```sh
npm run test:lint
npm run lint
npm run format:check
```
