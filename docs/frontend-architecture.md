# Архитектура фронтенда

`apps/web`: React 19 + React Compiler, React Router 8 (data router, ленивые страницы), TanStack Query 5, Tailwind 4 на токенах UI-кита. Правила импортов FSD проверяет ESLint, см. [fsd.md](fsd.md). Почему нет Redux, MobX и Zustand — [adr/0001-state-management.md](adr/0001-state-management.md).

## Ответственность слоёв

React здесь — только вид. Данные приходят из кэша запросов и сторов, решения о правах принимают правила из `@gwmt/contracts`, страница лишь соединяет готовые части.

| Слой       | Что лежит                                                                         | Пример                                                               |
| ---------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `app`      | роутер, гарды, скоупы, провайдеры, экран падения, инициализация сессии            | `router/routes.tsx`, `router/scopes/BoardScope.tsx`, `ui/ErrorBlock` |
| `pages`    | адрес, запросы, загрузка, ошибки, доступ, редиректы и сборка готовых блоков       | `BoardPage` + `BoardScreen`, `TaskScreen`, KPI-резолверы             |
| `widgets`  | самостоятельные блоки экрана, их карточки и Layout-композиты со слотами           | `kanban-board`, `task-detail`, `kpi-dashboard`, `profile-overview`   |
| `features` | действия пользователя, сгруппированные по сущности: мутации, формы, сторы скоупов | `task/change-status`, `comment/add-comment`, `board/workspace`       |
| `entities` | API и кэш, чистая доменная логика, «говорящие» компоненты над китом               | `TaskStatusSelect`, `CommentItem`, `getTaskTimerView`                |
| `shared`   | UI-кит, React-примитивы (`ErrorBoundary`, `AsyncBoundary`), DI, стор, роуты       | `createDi`, `createStore`, `ROUTES`, `formatDuration`                |

Сущности не знают друг о друге. Где нужна связь, работают слоты (IoC): `TaskCard` принимает `people` и `timerAction`, каркас — `renderBoardsPanel`, панель свойств — `renderRow`, `CommentItem` — `avatar`. Связь «комментарий дописан в деталь задачи» собирает фича `comment/add-comment`: она вызывает `createComment` из `entities/comment` и кладёт ответ в кэш через `appendTaskComment` из `entities/task`.

Один компонент — один файл, на любом слое, включая arrow-компоненты, function expressions, `memo` и `forwardRef`. Обёртка `memo(XBase)` и локальный `XBase` считаются одним компонентом. Правило проверяет ESLint; тестовые файлы могут объявлять несколько компонентов.

Страница — медиатор: её публичный `index.ts` экспортирует только страницы. `TaskPage` ставит границы загрузки и ошибок, `TaskScreen` читает задачу из кэша, исправляет адрес доски и собирает `ShellPage` с `TaskView` из `widgets/task-detail`. `TaskView`, `TaskLayout` и карточки живут вместе в этом виджете. Виджет может быть нужен лишь одной странице: повторное использование не является условием выделения.

Layout-композит переезжает вместе с блоком: Root и каждый слот лежат в отдельных файлах `widgets/<name>/ui`. Страница наполняет слоты готовыми виджетами, фичами и сущностями. Виджеты импортируют только features, entities и shared; друг друга они не импортируют. Страница соединяет их через публичные `@/widgets/<name>`. В `pages/*/model` остаётся только состояние страницы и адреса (`my-tasks-params`), в `widgets/*/model` допустима логика блока, а в `lib` — чистые утилиты, например цвета графиков.

`BoardScreen`, `ProfileScreen` и `MembersScreen` отделяют чтение suspense-запросов от границы загрузки и собирают блоки. `KpiScreen` читает выбранный спринт и записывает новый выбор в адрес; `FirstBoardRedirect` и `CurrentSprintRedirect` остаются отдельными резолверами: `useSuspenseQuery` не поддерживает `enabled`. Общий каркас двух страниц авторизации (`AuthLayout`, `AuthIllustration`) остаётся в слайсе `pages/auth`.

## Роутер

`app/router` разложен по ответственности, `routes.tsx` только собирает уровни:

```
app/router/
├─ routes.tsx           композиция: гард → global scope → каркас → модули
├─ router.ts            createBrowserRouter(routes)
├─ guards/              RequireAuth, GuestOnly, SessionPending
├─ scopes/              CurrentBoardScope (global), BoardScope (cross-module)
├─ layout/              AppShellRoute — каркас и список досок в его панели
├─ modules/             *.routes.ts — роуты одного модуля, ленивые страницы
├─ fallback/            RouteErrorBoundary, RouteFallback
├─ lib/lazy-page.ts     lazy-роут из публичного index.ts страницы
└─ testing/             мок сессии и общий сценарий интеграционных тестов
```

Интеграционные тесты лежат рядом с тем, что проверяют: `guards/guards.test.tsx`, `scopes/board-scope.test.tsx`, `modules/task.routes.test.tsx`. Все гоняют настоящее дерево `routes`.

## Скоупы зависимостей

Повторяют подход `dependency-scope`: зависимость живёт ровно там, где нужна. Начинаем с module scope и поднимаем только под реальную потребность.

```
RouterProvider
└─ RequireAuth
   └─ CurrentBoardScope ─────── global: CurrentBoardInjector (текущая доска, key = user.id)
      └─ AppShellRoute ──────── AppShellInjector (переключатель досок)
         ├─ /boards             module: поиск и фильтр списка — useState в BoardList
         ├─ /boards/:boardId ── cross-module: BoardScope → BoardWorkspaceProvider (key = boardId)
         │  ├─ index            канбан
         │  ├─ members          участники
         │  └─ tasks/:taskKey   задача
         ├─ /tasks/:taskKey     резолвер постоянной ссылки → /boards/:id/tasks/:key
         ├─ /my-tasks           module: фильтры в адресе
         ├─ /kpi                module: доска и спринт в адресе
         └─ /profile
```

| Скоуп        | Критерий                               | Что в нём                                      | Где создаётся                                     |
| ------------ | -------------------------------------- | ---------------------------------------------- | ------------------------------------------------- |
| global       | нужно трём и более несвязанным модулям | `authService`, `queryClient`, текущая доска    | синглтоны модулей; `scopes/CurrentBoardScope.tsx` |
| cross-module | нужно 2–3 связанным модулям            | рабочее пространство доски: колонка, подсветка | `scopes/BoardScope.tsx` на границе роутов доски   |
| module       | нужно одной странице                   | черновики форм, поиск списка, диалоги          | внутри страницы: `useState`                       |

### Cross-module scope доски

Канбан, участники и задача — три модуля одной доски. Общий стор `BoardWorkspace` хранит:

- выбранную колонку на телефоне;
- ключ открытой задачи для подсветки карточки после возврата.

Фильтры доски читаются из URL: `q` — поиск, `priority` — приоритет,
повторяющийся `assignee` — ID выбранных участников. Адрес — единственный источник
фильтров, без дублирования в сторе и без browser storage. Разбор и запись параметров
находятся в `pages/board/model`. Изменения заменяют текущую запись истории;
пустые фильтры удаляются из адреса. Ссылки на задачу и участников и возврат на доску
сохраняют параметры. Поэтому обновление страницы, отправленная ссылка и навигация
назад/вперёд восстанавливают выбранные фильтры.

Фильтр по людям не синхронизируется событиями: в работу идёт пересечение выбранных людей с текущими участниками доски (`effectiveFilters`). Удалённый, ставший гостем или убранный другим администратором человек не остаётся невидимым фильтром — без единого обработчика.

`authService` и `queryClient` — синглтоны модулей, а не DI-токены: ядро авторизации (`entities/auth/lib`) переносимое и нужно до React (транспорт API, мониторинг). Поэтому интеграционные тесты подменяют модуль `@/entities/auth` через `vi.mock`, а всё ниже сессии получают через провайдеры.

Роут знает, что нужно модулю, провайдер — только как хранить:

```tsx
// app/router/scopes/BoardScope.tsx
<BoardWorkspaceProvider
  key={boardId}
  createStore={() => createBoardWorkspaceStore({ boardId })}
>
  <Outlet />
</BoardWorkspaceProvider>
```

```tsx
// app/router/modules/board.routes.tsx
{
  path: ROUTES.BOARD.path,
  element: <BoardScope />,
  children: [
    { index: true, lazy: lazyPage(() => import('@/pages/board'), (page) => page.BoardPage) },
    { path: ROUTES.BOARD_MEMBERS.path, lazy: /* участники */ },
    { path: ROUTES.BOARD_TASK.path, lazy: /* задача */ },
  ],
}
```

Отличие от `charactersRoutes` из `dependency-scope`: там сервис создаётся прямо в массиве роутов, потому что не зависит от адреса. Здесь стору нужен `boardId` из адреса, поэтому `element` — маленький компонент, а `key` пересоздаёт стор при смене доски. Страницы читают плоский объект `useBoardWorkspace()` — состояние, производные и экшены, без знания о подписке.

## Данные

- **Чтение.** `entities/*/api` отдают `queryOptions`: фетчер парсит ответ zod-схемой контракта, ключ стабилен, `meta.tags` говорит, от каких данных зависит запрос.
- **Запись.** Мутации живут в фичах. Ответ-карточка кладётся в кэш точечно (`putTaskCardInCache`), зависимые данные сбрасываются по тегу: `invalidateTags(client, [QUERY_TAGS.tasks])`. Сущности изолированы и не знают ключей друг друга — теги работают как в RTK Query.
- **Оптимистичность.** Перенос карточки и звёздочка применяются сразу и откатываются по снимку при отказе сервера. Права проверяются до запроса теми же функциями, что и на сервере (`statusMoveError`, `can`), поэтому запрещённый ход не уходит в сеть.
- **Время.** Таймеры считаются от времени сервера. Поправка часов — свойство машины клиента, поэтому она одна на приложение: фетчеры передают `serverTime` в `syncServerClock` в момент ответа. Точечные записи в кэш после паузы или комментария её не сдвигают. Один общий тикер на все карточки.

## Загрузка и ошибки

Каждая страница обёрнута в `AsyncBoundary` из `shared/lib/react`: Suspense, собственный `ErrorBoundary` (без `react-error-boundary`) и сброс упавших запросов. Поэтому компоненты страниц пишут только счастливый путь. Границы — это поведение React, а не вид, поэтому они в `shared/lib`, а не в UI-ките. Запасной экран им передаёт страница, обычно это `UIRequestError` из кита.

Ошибки рендера внутри страниц уходят в Sentry через `reportRenderError`. Ошибки запросов там не дублируются — их уже отправил мониторинг кэша. На 404 и 403 `UIRequestError` показывает «не найдено» с путём назад, на остальное — текст сервера и «Повторить». Глобальный тост ловит фоновые ошибки и мутации; формы с `meta: { toast: false }` показывают ошибки под полями. Ошибки рендера вне страниц и упавшие чанки ловит `RouteErrorBoundary` и отправляет в Sentry. Экран падения приложения `ErrorBlock` лежит в `app/ui`: он нужен только слою `app`.

## Тесты

| Уровень           | Что проверяется                                                                                            | Где                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Чистая логика     | таймер, фильтры, правила переходов, KPI-трансформации, черновики форм, ключ доски, формат дат и чисел      | `*/model/*.test.ts`                        |
| Сторы и DI        | экшены, сохранение, разбор чужих данных, ошибки без провайдера                                             | `shared/lib/*`, `features/board/workspace` |
| Кэш и мутации     | оптимистичный перенос и откат, звёздочка, слияние карточки с деталью, комментарий в детали                 | `entities/*/api`, `features/*/*/model`     |
| Компоненты фич    | диалог задачи для рабочего и администратора, доска-гость по умолчанию, ошибки полей с сервера, поле оценки | `features/*/*/ui/*.test.tsx`               |
| Интеграция роутов | гарды, вход, регистрация, OAuth, cross-module scope доски, постоянная ссылка, задача по ролям, KPI         | `app/router/{guards,scopes,modules}`       |

Тестовые утилиты — `@/shared/lib/testing`: `createApiMock` (фейковый HTTP по методу и пути), фикстуры, проходящие zod-схемы контрактов, `renderRoutes` с настоящим роутером в памяти. Мокается только транспорт и сессия, всё остальное — настоящий код. Интеграционный тест падает, если какой-то запрос остался без мока (`api.unmatched`).

Общий сценарий интеграционных тестов роутера — `app/router/testing`. `setupRouterTest` сбрасывает сессию и хранилища и отдаёт мок API с двумя досками, `warmUpRoutes` в `beforeAll` заранее грузит ленивые страницы. Без прогрева первая страница каждого файла транспилировалась бы внутри `findBy*`, и таймаут мерил бы vite, а не поведение.

## Как добавить

**Страницу.** Слайс в `pages/<name>` с публичным `index.ts`, экспортирующим только страницы, адрес в `shared/routes`, роут модуля в `app/router/modules/<name>.routes.ts` через `lazyPage`, подключение в `routes.tsx` одной строкой. В `ui/<Name>Page.tsx` — чтение адреса, границы загрузки и ошибок, выбор ветки доступа или редиректа и композиция `ShellPage` с готовыми блоками. Отдельный `Screen` нужен только для ветки состояния, например suspense-запроса под `AsyncBoundary`. Презентационные блоки и их Layout-композиты помещаются в `widgets/<name>`, по компоненту на файл; страница импортирует их через `index.ts`. В `model` страницы остаётся состояние адреса и страницы.

**Действие.** Слайс в `features/<сущность>/<действие>`, например `features/task/link-tasks`: `model` — хук мутации или чистая логика, `ui` — компонент. Импортирует сущности и `shared`, другие фичи — нет, даже соседние в той же группе.

**Сущность.** Слайс в `entities/<name>`: `api` — запросы и `queryOptions`, `model` — типы и чистая логика, `ui` — «говорящие» компоненты. Если у данных свой жизненный цикл и свои действия, как у комментария, — это отдельная сущность, а не поле соседней. На бэкенде ей соответствует модуль `apps/api/src/modules/<name>`.

**Общее состояние для нескольких страниц.** Сначала проверить, не хватит ли кэша запросов или адреса. Если нет — стор в фиче (`createStore` + `createDi`), провайдер на границе нужной ветки роутов, тест на сохранение состояния между этими роутами.
